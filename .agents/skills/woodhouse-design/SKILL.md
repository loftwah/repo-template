# Required design entry path for new Woodhouse projects

Read AGENTS.md and the generated project's own product, security, art, data and release authorities. This file is a routing rule, NOT Impeccable, an installed engine or proof of use. Do not copy a template's fictional product/design context into a real project. MP already requires the actual skill without reminders.

Resolve the real agent harness and loaded Impeccable SKILL.md, path/revision, CLI/engine and global/plugin/project precedence. Read the upstream skill and current official release/setup guidance. Install/update via its supported route with reviewed versions, preserving customisations and backups outside discovery. A trusted local Woodhouse checkout supplies `scripts/impeccable-project.mjs` and `docs/IMPECCABLE.md`; do not execute moving remote scripts. Verify a fresh session selects Impeccable for meaningful UI work without naming it in the task. Verify supported hooks actually fire; preserve real trust approvals and document unsupported harness capabilities.

Run the resolved context launcher once for the actual target. Use existing project facts and recorded owner answers for PRODUCT.md; document the actual accepted visual system in DESIGN.md and relevant surface briefs. Do not infer absent business facts, overwrite accepted identity or demand answers already recorded. Follow upstream fallback honestly if the launcher cannot run.

Read and use shape/new-work, critique, audit and the targeted refinement playbooks appropriate to the task; read the craft floor before UI edits. A detector scan alone is not a design pass. Inspect rendered pixels and actual interactions at representative phone/desktop or native sizes, keyboard/focus/touch, contrast, overflow, loading/empty/error and reduced motion. Games need actual canvas/HUD/gameplay checks. Fix material findings and reinspect without needless redesign.

Record actual tool/harness/source/target, context/playbooks, findings, repairs or justified no-change, rendered interaction evidence and limits in the generated project's existing issue/PR/evidence. Setup, discovery, use, fixes, main and production are distinct. Runtime work requires main AND verified authorised production; tooling-only changes require main and focused checks. Never copy completed evidence from the template or another app.

Template owner: #2. Portfolio owner: https://github.com/loftwah/woodhouse-new/issues/160 . A file copied into a new repo is not proof that its local agent loaded or used the upstream skill. Register the new project's real coverage in the existing portfolio record; no new parallel registry or background service.
